# rokiz.net 루트 사이트

`www.rokiz.net`의 대문. GitHub Pages 사용자 사이트(`rokieyez.github.io`)라서
이 계정의 다른 프로젝트 사이트들이 자동으로 같은 도메인의 경로가 된다.

- `/` — 이 저장소 (대문)
- `/now` — 지금 (요즘 읽는 것과 만드는 것)
- `/notes` — 글 (글방 — 아래 참조)
- `/books` — [서가 뒤의 방](https://github.com/rokieyez/books) (개인 서재)

## 대문이 서재에 묻는 것

대문의 「서재에 N권이 서 있고…」 줄과 `/now` 의 「읽는 중」은 **서재의 공개
API 에서 그때그때 받아 온다.** 숫자를 손으로 옮겨 적으면 반드시 어긋난다.

- 권수는 **몸통 없이 세기만 하는 질의**로 받는다 (`Prefer: count=exact` + `Range: 0-0`) —
  오가는 것이 헤더뿐이라 무료 요금제의 전송량을 축내지 않는다.
  서재에서 하루 3.9GB 를 흘려 본 적이 있다 (books 저장소 CLAUDE.md 의 Egress 규칙)
- 쓰는 키는 서재의 **공개 키**(`sb_publishable_…`)이고 읽기만 한다
- **서재가 자고 있어도 대문은 열려 있어야 한다** — 못 물어보면 그 줄은
  아예 나타나지 않고, `/now` 는 서재로 가는 링크를 대신 보여준다
- 셈은 **그 방의 문 안에** 적는다 (`.door em` — 서재는 권수, 지금은 갈피가
  움직인 때, 글은 편수와 마지막으로 놓인 때) — 대문 한가운데 몰아 두면
  어느 방 이야기인지 알 수 없다. 가운데 남는 것은 「지금 펼쳐 둔 책」 한 문장뿐
- `/now` 의 「최근에 꽂은 책」은 서재의 `feed.xml` 을 그대로 읽는다. 같은
  도메인이라 담 너머로 부를 것이 없고, 「새로 들어온 것」을 정하는 규칙을
  이쪽에 베껴 두지 않아도 된다
- `/now` 맨 윗줄의 「갈피를 마지막으로 옮긴 것은 …」도 서재에서 온다.
  **이런 쪽은 「언제 적었나」를 손으로 적는 순간 그것부터 낡는다**

## 지난 지금 (`/now`)

`/now` 는 **덮어쓰는 쪽**이라 고칠 때마다 과거가 사라진다. 크게 바뀔 때
갈무리해 두면 그것이 곧 기록이 된다:

1. `now/index.html` 을 `now/<연도>-<달>.html` 로 복사한다 (예: `now/2026-09.html`)
2. 복사본에서 서재에 묻는 `<script>` 두 덩이를 지우고, 그때 화면에 있던
   값을 글자로 박아 둔다 — **갈무리는 그 시점의 사진이어야 한다.**
   그대로 두면 갈무리가 오늘 값을 따라가 버려 아무것도 남지 않는다
3. 복사본에 `<meta name="robots" content="noindex">` 와 canonical 을 그 주소로
4. `now/index.html` 의 「지난 지금」 절에서 `hidden` 을 지우고 목록에 한 줄

## 검색엔진에 알리기

- **구글·네이버**는 사람이 로그인해서 지도를 제출해야 한다
  (Search Console · 서치어드바이저). 대신해 줄 방법이 없다
- **빙·Yandex·Seznam** 은 IndexNow 규약을 쓴다 — `node tools/indexnow.mjs` 한 번이면
  두 지도의 주소를 전부 알린다. `--dry` 를 붙이면 보내지 않고 무엇을 보낼지만 보여준다
- 루트의 `<32자리>.txt` 는 IndexNow 열쇠다. **지우면 알림이 거부된다**

## 글방 (`/notes`)

글은 파일이 아니라 **Supabase 의 `notes` 표**에 산다. 브라우저에서 바로
쓰고 고칠 수 있고, 초고는 주인에게만 보인다 (RLS 가 막는다).

- `/notes/` 는 목록이자 **책상**이다. 아래 「열쇠」를 눌러 들어오면
  같은 쪽에서 쓰고 고치고 발행한다. 손님에게는 그냥 목록으로 보인다
- 로그인은 **암호와 메일 링크 둘 다** 된다. `shouldCreateUser: false` —
  이 문으로는 새 사람이 만들어지지 않는다
- supabase-js 는 **문을 열 때만** 내려받는다. 손님은 그 라이브러리를
  한 바이트도 받지 않는다

### 글을 올리거나 고친 뒤 반드시 돌릴 것

```
node tools/make-notes-pages.mjs   # 글쪽 + 집 지도
node tools/make-feed.mjs          # 집 피드
git add -A && git commit && git push
```

- `tools/make-notes-pages.mjs` 가 발행한 글마다 `notes/<슬러그>.html` 을 굽는다.
  **검색엔진과 링크 미리보기는 자바스크립트를 돌리지 않는다** — 표에만 있는
  글은 그들 눈에 빈 쪽이다. 굽지 않으면 아무도 읽지 못한다
- 같은 도구가 `/sitemap.xml` 을 통째로 다시 그린다. **손으로 고치지 말 것**
- 내린 글(`published` 를 끈 글)의 쪽은 다음 실행 때 지워진다
- 목록에서 발행한 글은 제 쪽(`.html`)으로, 초고는 이 쪽 안(해시)에서 펼친다.
  주인에게만 「고치기」 손잡이가 하나 더 붙는다 — 그것이 없으면 올린 글을
  다시 열 길이 없다

## 로봇이 보는 것

- `robots.txt` 는 **오리진 루트에서만 읽힌다** — `/books/robots.txt` 는 아무도 안 본다.
  그래서 도메인을 가진 이 저장소가 온 집안의 로봇 규칙을 맡는다.
- 지도는 방마다 하나씩이고 `robots.txt` 가 둘을 나란히 가리킨다:
  - `/sitemap.xml` — 이 저장소의 쪽 (`tools/make-notes-pages.mjs` 가 짓는다)
  - `/books/sitemap.xml` — 서재가 `node tools/make-book-pages.mjs` 로 스스로 짓는다 (책 544권)
- **방을 새로 열면 `tools/make-notes-pages.mjs` 의 `방` 목록에 한 줄 더한다** —
  지도는 그 도구가 짓는다. 그 방이 스스로 지도를 지으면 `robots.txt` 에
  `Sitemap:` 줄을 하나 더 얹는 쪽이 낫다.
- `og.png` (1200×630) 는 링크를 나눌 때 보이는 얼굴이다. 없으면 카톡·슬랙이
  회색 상자를 띄운다. 대문 디자인이 바뀌면 이것도 다시 그릴 것.
- 파비콘은 **둘**이다: `favicon.svg`(낮)와 `favicon-night.svg`(밤 — 열쇠구멍으로
  빛이 샌다). 대문의 스크립트가 보는 사람의 시계를 보고 18시~6시에 밤 것으로
  바꿔 단다. 정적 파일이라 시간을 스스로 알 수 없어 자바스크립트가 맡는다
- `404.html` 에는 `noindex` 를 둔다 — 「잠긴 문」이 검색 결과에 뜨면 안 된다.

## 규약

- 빌드 단계 없는 정적 HTML — 배포는 `git push`
- 새 방(섹션)을 열 때는 해당 프로젝트 저장소에 Pages를 켜면 경로가 저절로 생긴다
- **`footer` 를 `position: fixed` 로 바닥에 붙이지 말 것.** 화면이 낮으면
  (폰을 눕히면 360px) 본문 위에 겹쳐 앉는다 — 실제로 그랬다 (2026-09-03).
  `body` 를 `grid-template-rows: 1fr auto` 로 두어 흐름 안에서 비켜나게 한다.
