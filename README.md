# rokiz.net 루트 사이트

`www.rokiz.net`의 대문. GitHub Pages 사용자 사이트(`rokieyez.github.io`)라서
이 계정의 다른 프로젝트 사이트들이 자동으로 같은 도메인의 경로가 된다.

- `/` — 이 저장소 (대문)
- `/now` — 지금 (요즘 읽는 것과 만드는 것)
- `/notes` — 글 (글방 — 아래 참조)
- `/books` — [서가 뒤의 방](https://github.com/rokieyez/books) (개인 서재)

## 대문이 서재에 묻는 것

대문의 「서재에 N권이 서 있고…」 줄과 `/now` 의 「읽는 중」은 **서재의 공개
API 에서 그때그때 받아 온다.** 숫자를 손으로 옮겨 적으면 반드시 어긋난다.

- 권수는 **몸통 없이 세기만 하는 질의**로 받는다 (`Prefer: count=exact` + `Range: 0-0`) —
  오가는 것이 헤더뿐이라 무료 요금제의 전송량을 축내지 않는다.
  서재에서 하루 3.9GB 를 흘려 본 적이 있다 (books 저장소 CLAUDE.md 의 Egress 규칙)
- 쓰는 키는 서재의 **공개 키**(`sb_publishable_…`)이고 읽기만 한다
- **서재가 자고 있어도 대문은 열려 있어야 한다** — 못 물어보면 그 줄은
  아예 나타나지 않고, `/now` 는 서재로 가는 링크를 대신 보여준다
- 셈은 **그 방의 문 안에** 적는다 (`.door em` — 서재는 권수, 지금은 갈피가
  움직인 때, 글은 편수와 마지막으로 놓인 때) — 대문 한가운데 몰아 두면
  어느 방 이야기인지 알 수 없다. 가운데 남는 것은 「지금 펼쳐 둔 책」 한 문장뿐
- `/now` 의 「최근에 꽂은 책」은 서재의 `feed.xml` 을 그대로 읽는다. 같은
  도메인이라 담 너머로 부를 것이 없고, 「새로 들어온 것」을 정하는 규칙을
  이쪽에 베껴 두지 않아도 된다
- `/now` 맨 윗줄의 「갈피를 마지막으로 옮긴 것은 …」도 서재에서 온다.
  **이런 쪽은 「언제 적었나」를 손으로 적는 순간 그것부터 낡는다**

## 지난 지금 (`/now`)

`/now` 는 **덮어쓰는 쪽**이라 고칠 때마다 과거가 사라진다. 크게 바뀌기
**전에** 갈무리해 두면 그것이 곧 기록이 된다:

```
node tools/snapshot-now.mjs            # 이번 달로
node tools/snapshot-now.mjs 2026-09    # 달을 정해서
```

도구가 여섯 걸음을 대신한다: 복사 → 서재에 묻는 `<script>` 를 걷어 냄 →
지금 서재에 물어 그 값을 글자로 박음 → 제목·canonical → `noindex` →
「지난 지금」 목록에 한 줄.

**갈무리는 그 시점의 사진이어야 한다.** 묻는 코드를 남겨 두면 갈무리가
오늘 값을 따라가 버려 아무것도 남지 않는다 — 도구가 그것을 지운다.

갈무리한 뒤 `/now/` 를 새로 고쳐 쓰고, 지도와 피드를 다시 지으면 된다.
「이 달에 있었던 일」 같은 절은 갈무리 파일에서 손으로 다듬는다.

## 검색엔진에 알리기

- **구글·네이버**는 사람이 로그인해서 지도를 제출해야 한다
  (Search Console · 서치어드바이저). 대신해 줄 방법이 없다
- **빙·Yandex·Seznam** 은 IndexNow 규약을 쓴다 — `node tools/indexnow.mjs` 한 번이면
  두 지도의 주소를 전부 알린다. `--dry` 를 붙이면 보내지 않고 무엇을 보낼지만 보여준다
- 루트의 `<32자리>.txt` 는 IndexNow 열쇠다. **지우면 알림이 거부된다**

### 지우면 안 되는 파일 셋

루트에 이름이 해시처럼 생긴 파일이 셋 있다. 셋 다 **저쪽에서 우리 것임을
확인하는 표**라서, 청소하다 지우면 소유확인이 풀리고 지도 제출도 함께 끊긴다.

| 파일 | 누구 것 | 지우면 |
|---|---|---|
| `google3df5176203fc3615.html` | Google Search Console | 소유확인이 풀린다 |
| `naveraa4b6552831a8654c25b632f989eb9d4.html` | 네이버 서치어드바이저 | 소유확인이 풀린다 |
| `9ea4480d4cbad8983eaf5ad7e326b82c.txt` | IndexNow | 알림이 403 으로 거부된다 |

소유확인은 **한 번 하고 끝나는 일이 아니다** — 저쪽이 이따금 다시 확인하러
온다. 2026년 9월 3일에 둘 다 확인을 마쳤다.

## 글방 (`/notes`)

글은 파일이 아니라 **Supabase 의 `notes` 표**에 산다. 브라우저에서 바로
쓰고 고칠 수 있고, 초고는 주인에게만 보인다 (RLS 가 막는다).

- `/notes/` 는 목록이자 **책상**이다. 아래 「열쇠」를 눌러 들어오면
  같은 쪽에서 쓰고 고치고 발행한다. 손님에게는 그냥 목록으로 보인다
- 로그인은 **암호와 메일 링크 둘 다** 된다. `shouldCreateUser: false` —
  이 문으로는 새 사람이 만들어지지 않는다
- supabase-js 는 **문을 열 때만** 내려받는다. 손님은 그 라이브러리를
  한 바이트도 받지 않는다

### 글을 올리거나 고친 뒤 반드시 돌릴 것

```
node tools/make-notes-cards.mjs   # 링크 미리보기 카드 (제목을 고쳤으면 --force)
node tools/make-notes-pages.mjs   # 글쪽 + 집 지도
node tools/make-feed.mjs          # 집 피드
git add -A && git commit && git push
```

**카드를 먼저 굽는다** — 글쪽이 `og:image` 로 걸 카드가 이미 있어야 한다.
순서를 바꾸면 그 글만 집의 `og.png` 로 돌아간다 (깨지지는 않는다).

- `tools/make-notes-pages.mjs` 가 발행한 글마다 `notes/<슬러그>.html` 을 굽는다.
  **검색엔진과 링크 미리보기는 자바스크립트를 돌리지 않는다** — 표에만 있는
  글은 그들 눈에 빈 쪽이다. 굽지 않으면 아무도 읽지 못한다
- 같은 도구가 `/sitemap.xml` 을 통째로 다시 그린다. **손으로 고치지 말 것**
- 내린 글(`published` 를 끈 글)의 쪽과 카드는 다음 실행 때 지워진다
- `tools/make-notes-cards.mjs` 는 **헤드리스 크롬으로 카드를 찍는다.** canvas
  라이브러리를 들이지 않으려는 것이다 — 빌드 단계 없는 정적 사이트라는 규약이
  있고 크롬은 이미 있다. `--virtual-time-budget` 이 글꼴이 내려올 때까지
  크롬의 시계를 붙잡는다. 빼면 대체 글꼴로 굳은 카드가 나온다
- 이미 있는 카드는 다시 굽지 않는다. **제목이나 첫 문장을 고쳤으면 `--force`**

### 글에 책을 건다

`notes.book_id` 에 서재의 책 한 권을 걸 수 있다. 책상의 「이 글이 말하는 책」에
제목 몇 글자를 치면 서재에서 찾아 준다. 걸면 세 곳이 이어진다:

- 글쪽 아래에 그 책이 표지와 함께 선다
- 서재의 **서표 안**에 「이 책을 말한 글」이 뜬다 (사람이 보는 자리)
- 서재의 나눔 쪽에도 같은 줄이 들어간다 (로봇이 읽는 자리 — 그 쪽은
  사람을 곧장 서재로 넘긴다)

**외래 키는 일부러 걸지 않았다.** `books` 는 통째로 다시 들이기도 하는 표라,
걸어 두면 그 작업이 글 때문에 막힌다. 책이 사라지면 링크만 안 걸린다.

책을 걸거나 뗀 뒤에는 **양쪽 저장소의 도구를 다 돌린다** — 루트의
`make-notes-pages.mjs` 와 서재의 `make-book-pages.mjs`.
- 목록에서 발행한 글은 제 쪽(`.html`)으로, 초고는 이 쪽 안(해시)에서 펼친다.
  주인에게만 「고치기」 손잡이가 하나 더 붙는다 — 그것이 없으면 올린 글을
  다시 열 길이 없다

## 무엇이 저절로 돌고 무엇이 손인가

**이 집에서 무언가를 *만드는* 일은 전부 손이다.** 저절로 도는 것은 알림과
점검뿐이다. 글을 발행하고 도구를 안 돌리면 그 글은 검색에도 링크 미리보기에도
없다 — 발행했는데 아무도 못 읽는 상태가 된다.

| | 무엇이 | 언제 |
|---|---|---|
| 저절로 | IndexNow 알림 (`indexnow.yml`) | push 뒤 |
| 저절로 | 재는 자 시험 (`check-house.test.mjs`) | push 뒤, 집 점검 앞에 |
| 저절로 | 집 점검 (`check-house.yml`) | push 뒤 · 이레에 한 번 |
| 손 | `make-notes-cards` → `make-notes-pages` → `make-feed` | 글을 올리거나 고친 뒤 |
| 손 | (서재 저장소) `make-book-pages` | 책을 꽂거나 표지가 바뀐 뒤 |
| 손 | `snapshot-now` | `/now/` 를 크게 고치기 **전에** |
| 손 | `bake-now` | 읽는 중인 책이 바뀐 뒤 (끊겼을 때 펼 갈무리) |
| 손 | `bake-doors` | 대문 문 안의 셈이 눈에 띄게 달라진 뒤 |
| 손 | `check-broken` | 화면을 새로 내거나 색을 바꾼 뒤 |

서재 저장소에도 같은 점검 워크플로가 있다 — 그쪽은 따로 배포되므로
이 저장소의 push 만으로는 그 변화를 못 본다. 도구를 베껴 두지 않고
`raw.githubusercontent.com` 에서 받아 온다: 규칙이 두 벌이 되면 반드시 어긋난다.

**잊어도 조용히 지나가지 않는다** — `check-house.mjs` 가 DB 와 지도를 견주어
「발행 N편인데 글쪽은 M장」이라고 알려 준다. 이레에 한 번은 저절로 돈다.

## 점검이 봐 주는 것

`node tools/check-house.mjs` (배포 뒤·이레마다 저절로):

| 무엇 | 흠으로 잡는 때 |
|---|---|
| 쪽마다의 규칙 | 제목·설명·canonical·og·테마색·구조화 표식이 빠짐 |
| canonical ↔ 지도 | 두 글자가 다름 (한글 인코딩) |
| 안쪽 링크 | 죽은 링크 |
| **뒤처짐** | 발행 편수 ≠ 글쪽, 서가 권수 ≠ 나눔 쪽, 집 피드가 서재 피드보다 옛것 |
| **대문의 문** | 「지금은 N이 열려 있습니다」가 실제 문 개수와 다름 · 그 문장이 세 곳에 다 없음 |
| **DB** | Supabase 에 못 물음 (무료 요금제는 오래 안 쓰면 잠든다) |
| **도메인** | 만료 90일 전 |
| **인증서** | 만료 14일 전 |
| **「지금」** | `/now/` 를 90일 넘게 손대지 않음 |
| **열쇠** | 곳마다 다른 공개 열쇠를 씀 (쪽 4 · 도구는 `집.mjs` 한 벌 + `check-house` · 서재 `config.js`) |
| **때말** | 「며칠 전」을 말하는 세 자리의 규칙이 서로 다름 |
| **담는중** | 장서를 95% 넘게 옮겼는데 아직 「옮겨 담는 중」이라 말함 |
| **갈무리** | 마지막 갈무리 뒤로 달이 지났는데 `snapshot-now` 를 안 돌림 |
| **구운값** | 구운 지 60일이 넘은 `data-baked` 가 있음 |
| **해쪽** | 서재가 링크를 걸 `y/<해>.html` 이 아직 안 지어짐 |

`--all` 을 붙이면 지도의 549곳을 전부 걸어 본다 (느리다). `--local` 은
`localhost:8777` 을 본다.

**재는 자도 잰다** (2026-09-04). 이 도구가 곧 이 집의 테스트인데, 도구 자체를
검증하는 것은 「일부러 깨뜨려 보기」손작업뿐이었다 — 그러다 「때말」검사가 제
주석에 속았다. 그물을 안 타는 순수 함수(`뽑`·`남은날`·`코드만`·`사다리`)를
내놓고 `node --test tools/check-house.test.mjs` 가 견준다. 첫 시험이 바로 그
사연이다. 도구는 `import` 로 불리면 집을 걷지 않는다(`스스로` 문지기) —
그래서 서재 저장소가 파일 하나만 `curl` 로 받아 돌리는 길도 그대로 산다.

**배포는 자지 않고 묻는다.** 「120초 자기」는 배포가 2분을 넘기면 옛 사이트를
견주고 초록불을 켰다. Pages 빌드 API 로 이 커밋이 `built` 인지 15초마다 묻고,
10분 안에 안 끝나면 빨간불. 묻는 것 자체가 막히면 예전처럼 2분 자고 넘어간다.

**「지금」이 묵은 날은 git 으로 센다.** 쪽에 「언제 적었나」를 박아 두면
그것부터 낡기 때문이다. 그래서 워크플로가 `fetch-depth: 0` 으로 히스토리를
가져온다 — 기본값(깊이 1)이면 어느 파일이든 오늘로 보인다.

## 지도의 `lastmod` 는 git 이 정한다

`lastmod` 는 「이 쪽이 마지막으로 바뀐 날」이다. 도구를 돌린 날을 적으면
글 한 편 올릴 때마다 대문과 지금까지 「바뀌었다」고 말하게 되고, 거짓 신호가
되풀이되면 **검색엔진은 이 값 자체를 무시한다.** 그래서 `make-notes-pages.mjs`
는 `git log -1 --format=%cs` 로 그 파일의 마지막 손길을 읽는다. 글쪽만은
DB 의 `updated_at`/`published_at` 이 더 정확하므로 그것을 쓴다.

## 손과 눈

폰으로 오는 사람의 몸으로 재 본 결과 정한 규칙이다 (2026-09-03).

- **`--dim`(#9C8E74) 위에 얹는 `opacity` 의 바닥은 `.85`.** `--dim` 그대로는
  바탕(#171009) 대비 5.86 이라 넉넉하지만, `.6` 을 얹으면 2.86 으로 떨어져
  WCAG AA 의 4.5 에 한참 못 미친다. `.85` 가 4.55 다.
  **중첩하면 곱해진다** — 목록의 날짜(.75) 안에 읽는 시간(.6)이 들어 있어
  실제로는 0.45 였다. 안쪽 것은 걷고 바깥 하나만 남긴다
- **손가락이 닿는 자리는 24×24 를 넘긴다** (WCAG 2.2). 보이는 크기는 그대로
  두고 `::after` 로 넓힌다 — 바닥글 링크가 12×18 이었다. 문장 안의 인라인
  링크는 이 규칙에서 면제된다 (줄 높이에 매여 있으므로)
- **큰 클릭 대상에는 `-webkit-tap-highlight-color: transparent`** 를 두고
  `:active` 로 대신 대답한다. 브라우저가 덧그리는 판은 요소의 **네모난 상자**를
  따르므로, 위가 둥근 문 위에 네모가 한순간 떠오른다
- **재는 법**: 조상의 `opacity` 를 모두 곱하고 바탕색과 섞은 **실제 색**으로
  대비를 계산해야 한다. CSS 에 적힌 색만 보면 통과한 것처럼 보인다
- **자는 화면에 떠 있는 것만 잰다.** 「손과 눈」 회차가 통과라고 한 쪽에서
  뒤에 세 가지가 나왔다 (2026-09-03): ①고장 났을 때만 나타나는 글자
  (`.failwhy` 2.89), ②그때 아직 없던 내용이 생기며 나타난 글자
  (목록의 결 3.61 — 그날은 결이 달린 글이 없었다), ③다른 저장소의 쪽
  (서재 판권장 3.15). **고장난 상태와 빈 상태를 일부러 만들어 놓고 재야 한다.**

## 공개 열쇠 — 무엇이고, 갈 때 어디를 함께 가나 (2026-09-04)

`sb_publishable_…` 는 **공개해도 되는 열쇠**다. 화면 소스에 그대로 박혀 있고
그래야 한다 — 서재와 글방을 읽으려면 브라우저가 그 열쇠를 들고 가야 한다.
지킴이는 열쇠가 아니라 **RLS**(행 수준 보안)다: 이 열쇠로는 발행한 글과 꽂은
책만 읽히고, 초고는 오지 않으며, 쓰기는 아무것도 되지 않는다.

- **만료가 없다.** Supabase 의 publishable 열쇠는 사람이 갈기 전까지 산다 —
  그래서 「언제까지 유효한가」를 셀 것이 없고, `check-house` 도 남은 날을
  세지 않는다(도메인·인증서와 다른 점이다).
- **갈아야 할 때**: 프로젝트를 옮기거나, 열쇠를 회수(revoke)했거나, RLS 를
  고쳐 이 열쇠가 볼 수 있는 범위가 달라졌을 때.
- **갈 때는 열다섯 자리를 함께 간다.** 배포된 쪽 넷(`/`, `/notes/`, `/now/`,
  `/404.html`) · 이 저장소의 도구 열 · 서재의 `js/config.js`. **`check-house`
  의 `열쇠` 검사가 이 전부를 세어 견준다** — 하나라도 옛 열쇠로 남으면
  「곳마다 다른 열쇠」로 걸린다. 화면만 갈고 도구를 잊으면 그날은 멀쩡하고,
  다음에 도구를 돌리는 날에야 죽는다. 그 며칠을 없애려고 검사를 넓혔다.

## 한 해 뒤에도 참말인가 (2026-09-04)

시간이 흐르면 **저절로** 거짓이 되는 자리들을 훑고, 그 자리마다 검사를 세웠다.
지어 둔 것이 뒤처지는 것은 이미 잡고 있었지만, **아무도 손대지 않아도 낡는
것**은 아무것도 보고 있지 않았다.

### 도구가 어제 날짜를 박고 있었다

`new Date().toISOString().slice(0, 10)` 은 **UTC 날짜**다. 이 집을 짓는 사람은
한국(UTC+9)에 있으므로 **00:00~09:00 사이에 도구를 돌리면 어제가 박힌다** —
하루의 아홉 시간, 37.5%. 네 도구가 모두 그 자를 쓰고 있었다.

- 갈무리에 「9.3 기준」이라 적혀 있는데 실은 9월 4일에 구운 것이라면, 그
  갈무리는 자기가 언제 것인지를 틀리게 말한다. 갈무리의 뜻이 「언제 것인지
  밝힌다」에 있으니 이 하루는 그냥 넘길 일이 아니다.
- **달은 더 나빴다.** 매달 1일 새벽에 `snapshot-now` 를 돌리면 **지난달**
  파일로 저장되어, 이미 있는 갈무리를 덮어쓸 뻔했다.

`tools/오늘.mjs` 한 벌을 두고 넷이 그것을 쓴다 — 도구를 돌리는 사람의 달력을
따른다. 화면에 「9.4 기준」이라 적힐 때 그 9월 4일은 보는 사람의 것이어야지
그리니치의 것이 아니다.

### 어제 저녁 것을 「오늘」이라 말하고 있었다

「며칠 전」을 스물네 시간으로 나눠 세고 있었다. 그러면 **어제 저녁 여덟 시에
놓은 글을 오늘 아침에 보고도 「오늘 놓임」**이라 한다(재어 확인). 사람은 그것을
어제라고 안다. 세 곳 모두 **자정을 몇 번 넘었는가**로 바꿨다 — 보는 사람의
달력을 따른다. `check-house` 의 「때말」 검사도 경계뿐 아니라 **세는 법**까지
견주도록 넓혔다(경계가 같아도 세는 법이 다르면 답이 갈린다).

### 새로 세운 다섯 검사

|---|---|
| `담는중` | 「1,300여 권을 옮겨 담는 중」 — 다 옮긴 날 이 문장만 남아 거짓이 된다. 95% 를 넘으면 알린다 |

갈무리 중 가장 나중 것보다 뒤에 지나간 달이 있을 때만** 재촉한다.

## 「며칠 전」은 집 안에서 한 벌이다 (2026-09-04)

같은 갈피 시각이 **세 자리**에 걸린다 — 대문의 「지금」 문, `/now/` 의 첫 줄,
서재의 책상. 셋이 저마다 셈하다 보니 여섯 구간이 어긋나 있었다.

| 지난 날 | 대문·지금 | 서재 |
|---|---|---|
| 1일 | 어제 | **1일 전** |
| 10일 | 10일 전 | **1주 전** |
| 20일 | 20일 전 | **2주 전** |
| 365일~ | 1해 전 | **1년 전** |

같은 사실을 방마다 다르게 말하고 있었던 셈이다. 규칙을 하나로 맞췄다:

```
0일  오늘 · 1일  어제 · 2~29일  N일 전 · 30~364일  N달 전 · 365일~  N해 전
```

- **주는 쓰지 않는다.** 「2주 전」은 14~20일을 뭉뚱그린다 — 「20일 전」이 더
  정확하고, 두 곳이 이미 그렇게 말하고 있었다.
- **달은 열하나에서 멈춘다.** 서른 날로 나누면 364일이 「12달 전」이 되는데,
  열두 달은 한 해다. 셋 다 이 결함을 갖고 있었다 — 이 집은 2026년 9월에
  섰으므로 **아직 아무도 보지 못한 자리**였다. 한 해 뒤에 드러났을 것이다.

고칠 때는 세 곳을 함께 고친다:
`index.html` 의 `지난말()` · `now/index.html` · (서재) `js/app.js` 의 `agoOf()`.
**`check-house` 가 세 자리의 사다리를 뽑아 견준다** — 하나만 고치고 나머지를
잊으면 「때말 — 서로 다릅니다」로 걸린다. 열쇠를 견주는 것과 같은 뜻이다.

> 그 검사는 처음에 제 주석에 속았다. 어긋났던 사연을 주석에 적으며 「2주 전」
> 이라고 썼더니, 코드에서 주를 걷어낸 서재를 두고도 「주있음」이라 읽었다.
> 재는 자가 글을 코드로 오해한 것이다 — 이제 주석부터 걷고 잰다.

## 문 안의 셈도 구워 둔다 (2026-09-04)

- **대문의 문 셋은 처음 몇 초 동안 비어 있었다.** 문 안의 한 줄
  (「544권 · 27권 읽음」, 「2일 전」, 「1편 · 오늘 놓임」)은 서재와 글방에
  그 자리에서 묻는 값이라, 답이 오기 전에는 자리조차 없었다 — 처음 오는
  사람이 보는 것은 「방이 셋 있다」는 말뿐이었다. `tools/bake-doors.mjs`
  가 그 값을 `<em data-baked>` 안에 미리 구워 둔다.

- **「정적 파일의 숫자는 반드시 거짓이 된다」** — 대문에 오래 붙어 있던
  주석이고, 옳은 걱정이다. 그래서 굽는 방식을 둘로 나눴다.

  - **셀 수 있는 것은 다시 센다.** 「2일 전」처럼 시간이 흐르면 틀리는 말은
    글자로 굽지 않고 **그 시각(`data-at`)만** 심는다. 화면이 그것을 오늘
    기준으로 다시 세므로, 구운 지 한 달이 지나도 「한 달 전」이라 바르게
    말한다. 「지금」 문에 「언제 기준」 꼬리가 없는 이유다.
  - **다시 셀 수 없는 것은 언제 것인지 밝힌다.** 권수·편수는 늘어난다.
    서재가 답하면 그 자리에서 갈아 끼우고(`data-fresh`), 여섯 셈이 지나도
    끝내 답하지 못하면 그때만 「9.4 기준」이라고 꼬리를 단다.

- 재어 확인한 것: 끊지 않았을 때는 구운 값이 먼저 서고 넉 셈 안에 셋 다
  오늘 것으로 갈렸다(값이 같아 덜컹이지 않는다). 서재로 가는 길을 끊었을
  때는 구운 값이 남고 서재·글 문에만 「9.4 기준」이 붙었다.

## 끊겼을 때 하는 말 (2026-09-03)

- **`/now/` 의 「읽는 중」도 갈무리를 편다.** `tools/bake-now.mjs` 가 그때의
  목록을 `<ul id="reading" data-baked="YYYY-MM-DD">` 안에 구워 둔다. 서재가
  답하면 오늘 것으로 갈아 끼우고, 못 답할 때만 그것을 펴며 **언제 적 갈무리인지
  밝힌다**. 바로 아래 「최근에 꽂은 책」은 우리 서버의 피드를 읽어 늘 멀쩡했으니,
  한 쪽 안에서 한 줄만 죽어 있던 셈이다.

- **못 연 것과 비어 있는 것은 다르다** — 그리고 **못 읽은 것이 목록일 때
  글까지 없는 척하면 안 된다.** 글방은 발행한 글을 `notes/<슬러그>.html` 로
  옆에 놓아 두고도, 서재가 답하지 않으면 방을 통째로 비웠다. 이제
  `make-notes-pages.mjs` 가 `notes/index.html` 의 `<!--구운목록-->` 자리에
  발행한 글의 목록을 구워 두고, 못 읽었을 때 그것을 편다 (**초고는 굽지
  않는다** — 남의 눈에 보여서는 안 될 글이다). 자바스크립트가 꺼진 사람에게도
  같은 목록이 보인다.
- **끝나지 않는 기다림은 빈자리보다 나쁘다.** `/now/` 의 두 목록은 「서재에
  물어보는 중…」으로 시작하는데, 자바스크립트가 꺼져 있으면 묻는 이가 없는데
  묻는 중이라고 말한다. 머리의 `<noscript><style>` 로 그 줄을 걷고 한 줄로
  갈음한다 (`<noscript>` 안에 `<style>` 을 둘 수 있는 자리는 `<head>` 다).
- **방문자에게 기계 말을 하지 않는다.** 서재는 못 연 까닭으로
  `TypeError: Failed to fetch` 를 화면에 얹고 있었다. `app.js` 의 `까닭()` 이
  아는 꼴을 사람 말로 옮기고, 모르는 꼴만 원문을 남긴다 — 원문은 늘
  `console.error` 에도 남으므로 실마리가 사라지지는 않는다.
- **갈무리는 뒤처지면 거짓말이 된다.** `check-house.mjs` 가 구운 목록의
  슬러그를 발행한 글과 맞춰 본다 — 편수만 세면 편수가 같은 다른 글을 놓친다.

## 키보드로 걷는 사람 (2026-09-03)

- **집 전체에 놋빛 고리 하나.** 이 집은 곳곳에서 `outline` 을 끄고 제 방식
  (문이 들리고, 테가 밝아지고, 글자 색이 바뀐다)으로 대답한다. 그 대답은
  그대로 두되, 어디서든 반드시 보이는 고리를 **한 줄로** 덮는다:
  `:focus-visible { outline: 2px solid var(--brass) !important; outline-offset: 2px }`
  87곳의 `outline: none` 을 하나씩 걷는 대신 이렇게 하는 까닭은, 새 단추를
  만들 때마다 또 꺼질 자리이기 때문이다. **`!important` 는 여기서 옳다.**
- **고리는 요소 바깥에 그려진다** (`outline-offset` 이 양수). 대비를 잴 때
  요소 제 배경으로 재면 놋빛 단추 위의 놋빛 고리가 1.00 으로 나온다 —
  **부모의 배경으로 재야 한다** (2026-09-03에 이걸로 한 번 헛짚었다).
- **`el.focus()` 는 `:focus-visible` 을 켜지 않는다.** 재기 전에 진짜 키를
  한 번 눌러야 브라우저가 「키보드로 온 것」으로 친다. 그 전에 잰 값은
  「포커스 표시가 하나도 없다」는 거짓말이 된다.
- **서재에는 탭이 209번 걸린다** (그중 150이 책등). 첫 자리에 건너뛰는 길을
  냈다: `<a class="skip" href="#desk">책등을 지나 책상으로</a>`.
  숨길 때 `display:none` 을 쓰면 탭이 아예 닿지 않으므로 화면 밖으로 밀어 둔다.

  빛이 샌다). 대문의 스크립트가 보는 사람의 시계를 보고 18시~6시에 밤 것으로
  바꿔 단다. 정적 파일이라 시간을 스스로 알 수 없어 자바스크립트가 맡는다
- `404.html` 에는 `noindex` 를 둔다 — 「잠긴 문」이 검색 결과에 뜨면 안 된다.

## 규약

- 빌드 단계 없는 정적 HTML — 배포는 `git push`
- **도구가 함께 쓰는 것은 `tools/집.mjs` 한 벌이다** — 공개 열쇠·REST 밑동·`esc`. 여섯 파일에 복붙된 `esc` 중 하나가 따옴표를 빠뜨리고 있었다 (2026-09-04). `check-house.mjs` 만은 혼자 선다 — 서재 저장소가 그 파일 하나만 받아 돌린다
- 도구는 Node 22 (`.nvmrc`) — CI 와 같은 판
- 새 방(섹션)을 열 때는 해당 프로젝트 저장소에 Pages를 켜면 경로가 저절로 생긴다
- **`footer` 를 `position: fixed` 로 바닥에 붙이지 말 것.** 화면이 낮으면
  (폰을 눕히면 360px) 본문 위에 겹쳐 앉는다 — 실제로 그랬다 (2026-09-03).
  `body` 를 `grid-template-rows: 1fr auto` 로 두어 흐름 안에서 비켜나게 한다.
